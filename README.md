# 智能多媒体信息展示终端系统 (HX4S20C, 2026 FPGA 创新设计赛 安路赛项 选题1)

基于 **APUG092_HDMI1.4b_Transmitter** 例程改进, 芯片 EG4S20BG256 (HX4S20C 开发板).
原例程只能按物理扇区搜索 4 张 BMP 并轮播; 本工程重写了 TF 卡加载、播放控制、视频合成与音频通路.

完整版《设计参考例程》文档见 **[设计参考例程文档.md](设计参考例程文档.md)**.

## 1. 功能一览

| 功能 | 实现 |
|------|------|
| 显示输出 | HDMI **1280×800 @ 59.9 Hz (16:10)**. 画面按 640×400 合成, 输出端 `video_scale2x` 把每个像素 2×2 复制放大; 1920×1200 等 16:10 显示器会等比放大 1.5 倍铺满全屏, **无黑边、不变形** (见第 4 节 “1280×800 输出”) |
| 上电快速响应 | PLL 锁定后约 **1 帧内** 即输出动态开机画面 (渐变背景 + 标题“智能多媒体信息展示终端系统” + 加载进度条 + 卡状态 + 按键/SW3/SW4 操作提示, 各行自动水平居中), 不等待 TF 卡; 首图加载完成后以转场进入 |
| 多图片切换 | 最多 **16 张** BMP; TF 卡可**按文件夹分类** (`IMG\` `MUSIC\` `SUB\`), 根目录 `PLAY.CFG` 播放列表设置**播放顺序与每张图的显示秒数**; KEY3 短按下一张 / 长按上一张; KEY2 短按开关自动轮播 (默认每张 4 s) |
| 任意分辨率图片 | 参照第十三讲 “图片缩放与缩略图” 扩展要求 3: BMP 宽高 **16~4096** 任意 (24/32 bit 非压缩, 每行补齐、自下而上 / 自上而下存储都支持), 加载时由 `bmp_fit_scaler` **等比缩放 (最近邻)** 到 640×400, 比例不同时上下或左右**补黑边居中**, 不变形; 不支持的格式按损坏图片跳过 (见第 4 节 “任意分辨率图片”) |
| 零等待切换 | SDRAM 内 6 个帧槽做图片缓存, 以当前图片为中心预取 {f, f+1, f+2, f-1, f+3, f+4}, 命中即切换 |
| 转场特效 | 8 种: 淡入淡出、横向擦除、纵向擦除、圆形展开、百叶窗、马赛克、随机溶解、黑场过渡, 另有"轮换"模式; KEY2 长按切换 |
| OSD 叠加 | 顶部信息栏 (轮播图标/序号/文件名/**图片原始分辨率**/特效/音频/标题, 轮播开关由第 1 列 ▶/❚❚ 图标表示; 按键或拨动 SW4 时弹出, 无操作 5 s 自动隐藏, 自动轮播换图不弹出), 底部半透明滚动字幕 (SUB.TXT, 支持中文字库 SUB.FNT), 加载/错误提示 |
| 显示参数调节 / 画面模式 | 拨码开关 **SW3** 打开后在屏幕中央弹出 OSD 菜单: **画面模式** (正常 / 日间 / 夜间 / 护眼 四种预设, 一键设置下面四项) + **亮度 / 对比度 / 色温 / 伽马 / 音频输出音量** (各 0~16 级, 数值条 + 级别数字) + “复位”. 亮度/对比度沿用第十四讲公式, 再串接每通道色温增益 (偏暖 = 低蓝光护眼) 与伽马曲线 (提亮 / 压暗暗部), 四步合成一张 256 项 RGB 查找表, 每帧场消隐期间按本帧参数重算 (整帧一致, 像素通路只查表、不用乘法器); 只作用于图像, OSD 文字不受影响; 音量为 2 dB/级 的增益表 (0 = 静音) |
| 音频频谱可视化 | 拨码开关 **SW2** 打开后, 在底部字幕上方叠加 **沉浸式** 频谱 (参照第十二讲 / 赛题解析 FFT 频谱方向): 硬件 1024 点 FFT, 24 个对数频段的频谱柱 (绿/黄/红, 快升慢落) + 白色峰值帽 + 两端左右声道细电平条, 背景完全透明. 取 HDMI 实际输出的样本 (含音量调节), 所见即所听; 显示值在帧边界更新, 不撕裂 |
| 应急报警 | 参照第十六讲 “应急信息发布终端”: 拨码开关 **SW1** 布防, 外接 **MQ-2 烟雾传感器** / **火焰传感器** (J1 扩展口) 或 **KEY1** (模拟传感器) 触发, 报警画面与终端日志显示触发来源. 触发后 **抢占一切**: 下一帧整帧硬切到全屏报警画面 (不用转场, 下部滚动预置疏散指引字幕), 警笛经 HDMI 播放 (不受音量/静音影响), 板载蜂鸣器同频鸣响, 数码管显示报警时长; 报警锁存到 SW1 拨回 0. 画面与声音全部由逻辑生成, 不依赖 TF 卡 |
| 第二屏运维终端 | 开发板另一个 HDMI 口 (**HDMI1**, 原理图 J7) 接 **1024×600** 小屏, 显示 OSD 风格的运维终端: 标题栏 + 运行时间, 三个实时状态面板 (存储与系统 / 播放状态 / 画面与音频, 含数值条), 15 行滚动**事件日志** (TF 卡状态变化、扫描结果、换图、菜单、画面模式、报警布防/触发/解除、音源、特效等自动记录, 带时间戳与 INFO/WARN/ERROR/ALARM 级别着色), **命令行**: 外接 **4×4 轻触开关矩阵键盘**, A/B 选命令、数字输参数、# 执行, 可反向控制主屏播放器 (跳到第 n 张 / 上下张 / 画面模式 / 亮度 / 音量 / 特效 / 轮播 / 触发报警), 结果写入日志. 独立第 4 个 PLL (50 / 250 MHz), 自写 TMDS 编码 (DVI), 主屏通路不受影响 (见第 2 节 “第二屏运维终端”) |
| WAV 音频 | TF 卡中第一个 WAV 作背景音乐, 8/16 bit、单/双声道、8k~48kHz, 经 **HDMI 音频** 以 48 kHz 输出, 播完循环; 无 WAV 时可切内置旋律 (小星星). 推荐由 PC 工具转成 48 kHz (与第十一讲相同, 样本与输出帧一一对应, 不经硬件插值), 其他采样率由硬件线性插值. 8192 样本 FIFO (8 块 BRAM32K), 水位低于 5/8 时连续读取 WAV 扇区直到接近满; 参照第十一讲 `wav_stream_player`: 预填充到半满才开始放, 读空时暂停 (不消耗、不插值旧样本), 回到半满再从断点继续, 音调不变 |
| 可靠性 | 位流固化到 SPI Flash, 上电自启; 复位异步置位、同步释放 (三个 PLL 全部锁定后才释放), SDRAM 初始化完成后才开始读 TF 卡 (见第 6 节); 单扇区读超时 (250 ms) 时只复位 TF 卡控制器并重读该扇区 (最多 2 次), 播放位置和图片缓存都保留, 音乐不会从头开始; 仍失败才按拔卡处理, 插回后重新扫描; 空闲心跳: 连续 0.5 s 没有读卡 (图片全部已缓存、测试音模式下 WAV 不消耗) 时读一次分区引导扇区并核对 FAT32 卷序列号, 空闲时拔卡 / 换卡也能发现, 控制器重新初始化后同样核对, 换了卡就重新扫描; 损坏图片自动跳过并提示 |

## 2. 操作说明

### 按键 (低有效, 16 ms 消抖, 长按 0.8 s)

| 操作 | 功能 |
|------|------|
| KEY3 短按 | 下一张 |
| KEY3 长按 | 上一张 |
| KEY2 短按 | 自动轮播 开/关 |
| KEY2 长按 | 切换转场特效 (0~7 固定, A = 轮换) |
| 拨码开关 SW4 (C5) | 音源: `0` = WAV 播放, `1` = 测试音 (内置旋律小星星); 随时拨动立即切换 |
| 拨码开关 SW3 (C6) | `1` = 进入显示参数调节菜单 (见下), `0` = 退出, 参数保持 |
| 拨码开关 SW2 (C7) | `1` = 显示音频频谱 (见下), `0` = 关闭; 与按键、菜单互不影响, 开机画面期间不显示 |
| 拨码开关 SW1 (C8) | 应急报警布防: `1` = 布防 (KEY1 可触发), `0` = 撤防, 同时解除正在进行的报警 |
| KEY1 (B2) | 模拟传感器: SW1 = 1 时按下即触发应急报警 (见下) |
| J1-27 (K16) `smoke_n` | MQ-2 烟雾传感器 DO (低有效, 内部上拉, 不接时无效) |
| J1-28 (M16) `fire_in` | 火焰传感器 DO (低有效, 内部上拉, 不接时无效; 极性由 `player_ctrl` 参数 `FIRE_HI` 选择) |

转场期间的按键会被记住, 转场结束后立即执行.

### 显示参数调节 (SW3 = 1)

参照第十四讲 “亮度对比度调节”, 并按第十六讲应用场景 (应急屏 / 广告屏的昼夜模式) 扩展了画面模式、色温与伽马.
SW3 拨到 `1` 后屏幕中央出现半透明菜单, 此时两个按键改为调节参数
(不再换图、不开关轮播、不切特效; 自动轮播计时暂停), SW3 拨回 `0` 后按键恢复原功能, 调好的参数保持到复位/断电.

| 操作 | 功能 |
|------|------|
| KEY3 短按 | 下一项 (模式 → 亮度 → 对比度 → 色温 → 伽马 → 音量 → 复位 → 模式) |
| KEY3 长按 | 上一项 |
| KEY2 短按 | 当前项 +1 (最大 16); 在 “模式” 项为下一个预设 |
| KEY2 长按 | 当前项 -1; 继续按住每 150 ms 再 -1 (最小 0); 在 “模式” 项为上一个预设 |
| 在 “复位” 项按 KEY2 | 全部恢复默认 (模式 正常, 音量 16) |

| 参数 | 级别 | 默认 | 效果 |
|------|------|------|------|
| 亮度 | 0~16 | 8 | 增益 = 级别 / 8, 即 0 ~ 2.0 倍 (8 = 原亮度, 0 = 全黑), 超过 255 饱和 |
| 对比度 | 0~16 | 8 | 以 128 为中心拉伸, 系数 = 级别 / 8 (8 = 原对比度, 0 = 全屏中灰, 16 = 2 倍) |
| 色温 | 0~16 | 8 | 每通道增益: 8 = 原色; 偏暖 (小) 时 G、B 减小, 0 级 G ×0.875 / B ×0.625 (低蓝光, 护眼); 偏冷 (大) 时 R、G 减小, 16 级 R ×0.69 / G ×0.91 |
| 伽马 | 0~16 | 8 | γ = 2^((8 − 级别) / 8), 即 0.5 ~ 2.0 (8 = 1.0 原样); 级别大提亮暗部 (夜间看清细节), 级别小压暗暗部 (强光下更通透) |
| 音量 | 0~16 | 16 | 每级 2 dB: 16 = 0 dB (原音量), 13 = -6 dB, 10 = -12 dB, 1 = -30 dB, 0 = 静音; WAV 与测试音都起作用 |

画面模式 (预设, 选中后可再单独微调各项; 菜单显示最近一次选择的模式名):

| 模式 | 亮度 | 对比度 | 色温 | 伽马 | 适用 |
|------|------|--------|------|------|------|
| 正常 | 8 | 8 | 8 | 8 | 默认, 原样显示 |
| 日间 | 11 | 10 | 9 | 7 | 白天 / 强光环境: 更亮、对比更强、略偏冷 |
| 夜间 | 5 | 7 | 4 | 10 | 夜间 / 暗环境: 降亮度、偏暖, 提亮暗部保留细节 |
| 护眼 | 7 | 8 | 1 | 8 | 长时间近距离观看: 强暖色、低蓝光 |

实现 (`player/color_lut_gen.v`): 亮度 → 对比度 → 色温 → 伽马 四步合成一张 256 项 × RGB 的查找表.
每帧 VS 下降沿按本帧参数重算 (一个乘法器分时复用, 每项 10 拍, 共 2560 拍), 在第一行有效像素之前
(场消隐 11 行 × 760 = 8360 拍) 写完, 所以整帧参数一致, 调节时不会上下半屏不同. 像素通路只查表,
原来亮度、对比度两级的 6 个乘法器省掉了. 伽马曲线 17 级 × 256 项存于 `player/gamma_rom.v`, 色温增益表在
`player/color_temp.vh`, 均由 `python/gen_gamma_rom.py` 生成 (仿真检查直接 import 同一份数据).
色温 8 / 伽马 8 时与原第十四讲公式逐位相同.

每次打开菜单光标都从 “模式” 开始. 菜单每行: 光标 ▶、名称、16 格数值条、级别数字 (模式行为模式名); 最下一行是按键说明.
菜单新增 10 个汉字 (模 色 温 伽 常 日 间 夜 护 眼) 后共 138 个, 内置汉字区只能放 128 个, 多出的 10 个由 `gen_osd_rom.py` 自动放到 OSD 字库未用的控制码 0x09~0x1E.

### 音频频谱 (SW2 = 1)

参照第十二讲 “音频可视化” 与赛题解析第 20 页 (PCM → FFT/DFT → 频谱能量渲染叠加). 最初做的是时域波形,
但音乐由很多频率叠加、没有固定周期, 16 ms 的瞬时波形每帧都完全不同, 看起来杂乱; 改为频谱柱后, 复杂音乐也稳定易读
(鼓点在左侧低频段跳动, 人声在中间, 镲片在右侧).

| 项目 | 实现 (`player/audio_spectrum_osd.v`) |
|------|------|
| 样本来源 | HDMI 实际发出的样本 (`I2S_receiver` 输出, 已含音量), 左右声道平均, 写入 1024 点环形缓冲 (BRAM) |
| 变换 | 每帧对最近 1024 个样本 (21 ms, 帧间重叠) 加 Hann 窗, 做 1024 点原位基 2 DIT FFT (10 级 x 512 蝶形, 每级除 2 防溢出); 顺序运算只用 1 个蝶形 (4 个乘法器), 约 4.2 万拍 = 2.24 ms (video_clk 18.75 MHz), 远小于一帧 16.7 ms |
| 旋转因子 / 窗 | 共用一张 1/4 周期正弦表 (257 x 15 bit, `python/gen_fft_tables.py` 生成 `fft_tables.vh`) |
| 频段 | 24 段, 约 50 Hz ~ 16 kHz 按对数等分 (每点 46.9 Hz, 低频每段 1 点, 高频每段最多 74 点); 每段取各点幅度 (max + min/2 近似) 的最大值 |
| 刻度 | dB: 1/4 倍频程 = 1.5 dB/格, 32 格 = 48 dB; 加 +3 dB/倍频程倾斜补偿 (以 1 kHz 为 0), 低音多的音乐看起来也均衡 |
| 动态 | 柱高 快速上升、每帧回落 1 格; 白色峰值帽保持 20 帧后每帧回落 1 格; 显示值只在帧开始 (消隐期) 更新, 不撕裂 |
| 省电 | SW2 关闭时不做 FFT, 柱子逐帧回落到 0 |
| 资源 | 数据 RAM 1024 x 36 bit + 样本缓冲 1024 x 16 bit (共 6 块 BRAM9K), 5 个 DSP 乘法器 |

- 位置 (640×400 坐标): x 128~511, y 332~363, 紧贴底部字幕上方、水平居中 (屏幕上 768×64); 24 根柱, 每根 12 像素宽、间隔 4 像素;
  颜色 绿 (0~19 格) / 黄 (20~25) / 红 (26~31); 两端细竖条为左右声道电平 (L x 120~122, R x 517~519).
- 背景完全透明: 柱、峰值帽、电平条以外的像素保持原图 (仿真逐像素核对).
- 样本在 `pix_clk` 域锁存并翻转 `aud_tgl`, 合成器在 `video_clk` (= `pix_clk`/4, 同源) 检测翻转后取用, 样本保持 1/48k s, 不需要 FIFO.
- 频谱颜色和菜单一样不受亮度/对比度影响. 参数菜单 (SW3) 与频谱可同时打开, 互不遮挡.
- FFT 的正确性: `tb_spec_unit` 导出进入 FFT 的样本和 1024 点结果, `check_spec.py` 用相同定点算法逐位核对, 并与浮点 FFT 比较 (纯音 SNR 约 60 dB).

### 应急报警 (SW1 = 1, 烟雾 / 火焰传感器 / KEY1 触发)

参照第十六讲 “应急信息发布终端” 案例: 紧急插播硬切 + 告警音 + 告警音频谱化 + 蜂鸣器听觉冗余.

| 项目 | 实现 |
|------|------|
| 触发 | `player_ctrl`: SW1 与 KEY1 各 16 ms 消抖; SW1 = 1 时 KEY1 按下 (按电平), 或下述传感器判定有险情, 或终端 `alarm` 命令, 即报警. **锁存**: 松开 KEY1 不解除 (传感器恢复不代表险情已排除, 需人工确认), 只有 SW1 拨回 0 才解除 |
| 外接传感器 | MQ-2 (`smoke_n`, 低有效) 与火焰传感器 (`fire_in`, 低有效, 所用模块检测到火焰时 DO 输出低; 高有效的模块把 `FIRE_HI` 改为 1, 并把 pin.adc 中 M16 改为 PULLDOWN) 模块的数字输出 DO (门限由模块上的电位器调). 2FF 同步后每 1 ms 采样做**漏桶积分**: 有效 +1, 无效 -1 (不低于 0), 累计到门限判定有险情, 回落到 0 才清除. 火焰门限 200 ms (`FIRE_MS`): 火苗闪烁使 DO 断续也能累计, 100 ms 以内的干扰不触发; 烟雾门限 1 s (`SMOKE_MS`): 浓度在门限附近来回跳也能累计. MQ-2 加热丝上电需预热, 上电后 60 s (`PREHEAT_MS`) 内忽略烟雾输入, 终端状态显示 “MQ-2 未就绪”. 传感器仍有效时撤防再布防会立即重新报警 |
| 触发来源 | `alm_src` 在触发时锁存: 0 KEY1, 1 烟雾, 2 火焰, 3 终端命令 (同时满足时 火焰 > 烟雾 > KEY1 > 终端). 报警画面说明行前半随来源变为 “检测到明火” / “检测到烟雾” / “有危险发生”; 终端日志为 `ALARM !! 火警 !! FLAME` / `ALARM !! 烟雾报警 !! MQ-2` / `ALARM !! 应急报警触发 !!` |
| 接线 | MQ-2: VCC → J1-11 (5V), GND → J1-12, DO → J1-27. **MQ-2 模块的 DO 上拉在 5V 上, 必须分压** (DO 串 10 kΩ 到 J1-27, J1-27 再接 20 kΩ 到 GND; 或把模块上的 DO 上拉电阻改接 3.3V). 加热丝约 150 mA. 火焰传感器: VCC → J1-29 (3.3V), GND → J1-30, DO → J1-28 (3.3V 供电, 可直连) |
| 抢占 | 报警期间 KEY3 / KEY2 不响应, SW3 菜单强制关闭, 自动轮播暂停, 音源切到警笛 (`amode = 3`); 播放状态机与 TF 卡加载照常运行, 解除后回到原来的图片, WAV 从断点继续 (报警期间不读 FIFO) |
| 画面 (`player/alarm_screen.v`) | 合成器在帧开始锁存报警状态, 下一帧整帧切换, 不撕裂; 报警画面盖住图片 / 开机画面 / 信息栏 / 菜单 / 字幕, 不受亮度对比度影响. 深红↔亮红缓慢脉动 (约 1 s 周期, 低于 3 Hz 闪烁安全限), 上下黄黑警示斜纹 (滚动), 大标题 “紧急警报” 白/黄每 0.5 s 交替, 两侧警告三角, 说明 “有危险发生 / 检测到烟雾 / 检测到明火 · 请立即疏散” (前半按触发来源) / EMERGENCY ALARM / “报警持续 mm:ss” 计时 / 操作提示 |
| 滚动应急字幕 | y 326~361 暗色字幕带 (上下黄线) 内滚动预置疏散指引 “请保持冷静 · 沿安全出口指示有序撤离 · 切勿乘坐电梯 · 听从现场工作人员指挥” (微软雅黑粗体 20 px, 整条 739 像素宽): 每帧左移 1 像素, 报警开始的第一帧从屏幕右边外进入, 滚完一遍 (约 23 s) 后重新进入 |
| 文字点阵 (`player/alarm_rom.v`) | `python/gen_alarm_rom.py` 用微软雅黑粗体 / Arial / 宋体渲染, 1 bit/像素, 7772 字节 (BRAM, 含滚动字幕 1953 字节, 说明行前半 3 种各 551 字节); 不占 OSD 字库 |
| 频谱 | 报警画面上不显示频谱 (SW2 打开也不叠加), 报警期间 FFT 停止运算 |
| 警笛 (`player/audio_i2s_player.v`) | 600 Hz ~ 1500 Hz 线性往返扫频 (升 1 s / 降 1 s), 削顶三角波 (梯形, 约 -6 dBFS), 不受音量 / 静音设置影响 |
| 蜂鸣器 | H11 输出与警笛同频的方波 (板载无源蜂鸣器, 需板上 SW5 使能); 非报警时恒为 0 |
| 数码管 | `ALAr01.25` = 已报警 1 分 25 秒 (最大 99:59) |
| 可靠性 | 画面、文字、警笛全部由逻辑实时生成, 不依赖 TF 卡 / SDRAM: 开机画面阶段、拔卡、图片未加载时同样能报警 |

顶部信息栏在以下情况弹出, 之后 5 s 内没有新操作就自动隐藏:
按任意键 (换图 / 轮播开关 / 切特效)、拨动 SW4、按键换图的新图出现时、上电或重新插卡后显示第一张图时.
自动轮播换图时不弹出 (加载中提示与进度条也不显示); 图片损坏的提示照常弹出约 2 s.

信息栏布局 (80 列, 每列 8 像素): 第 1 列轮播图标, 3~7 序号 `03/12`, 10~17 文件名, 19~27 **图片分辨率** (BMP 原始宽高,
如 `1920x1080`, 自上而下存储的负高度取绝对值; 加载中 / 图片错误提示占用 10~21 列时不显示), 29~36 特效, 38 音乐图标,
39~46 音源, 47~52 采样率 (没有 WAV 时显示 “无文件”), 54~79 标题.
分辨率由加载器在读到 BMP 头 (偏移 34) 时转成 ASCII (逐位减 1000/100/10/1, 约 50 拍), 写入文本 RAM 768 + 图片号 × 16,
合成器按当前图片号读出, 与文件名同一条字符通路, 不增加 BRAM.

### 数码管 (8 位, 从左到右阅读)

```text
开机阶段:  [-][-] [ ] [总数十位][总数个位] [状态机][ ] [卡状态.]                  例:  -- 12 3 2.
播放阶段:  [序号十位][序号个位] [-] [总数十位][总数个位.] [状态机] [特效][音频.]   例:  03-12.1 5≡
应急报警:  [A][L][A][r] [分十位][分个位.] [秒十位][秒个位]                         例:  ALAr01.25
```

- `03-12` 即第 3 张 / 共 12 张; 总数个位的小数点亮 = 自动轮播开启
- 状态机 (左起第 6 位, 赛题解析 slide 18 官方框图的状态显示): `1` 空闲, `2` 搜索 BMP (初始化 TF 卡 / 扫描 FAT32 目录),
  `3` 写入 SDRAM (加载器正把图片写入帧槽, 含后台预取), `4` OSD 叠加 (菜单 / 顶部信息栏 / 转场叠加中), `E` 无卡 / 文件系统错误 / 无图片;
  同时满足时按 2 > E > 3 > 4 > 1 显示
- 卡状态: 0 初始化, 1 扫描, 2 就绪, 3 无卡, 4 文件系统错误, 5 无图片
- 特效: 0~7 为固定特效, `A` 为轮换
- 音频 (最右一位): WAV 模式显示音量电平条 (`_` 弱 / `=` 中 / `≡` 强, 约 85 ms 刷新一次, 随音乐跳动属正常),
  `P` 为内置旋律 (SW4 = 1)
- 音频位的小数点亮 (保持约 0.5 s): WAV 播放中 FIFO 被读空, 即 TF 卡供数跟不上.
  此时播放暂停 (静音保持), 等 FIFO 回到半满 (约 85 ms @48k) 后从断点继续, 不跳段、不变调.
  若经常亮, 请换读取更快的 TF 卡, 或把音乐转成单声道 (见第 3 节)
- 扫描驱动 `player/seg_scan8.v` 参照第三讲 `seg7_panel.v`: 位选低有效独热码, 每位 8192 个时钟 (8 位一圈 1.31 ms);
  管脚按官方 HX4S20 例程 (`seg_sel[0..7]` = D11 E11 F10 C13 E10 E12 E16 F16, `seg_sel[7]` 为最左位).
  旧版只用了 6 位且位序反了, 读起来是倒序的

### 第二屏运维终端 (HDMI1, 1024×600)

开发板另一个 HDMI 口 (HDMI1, 原理图 J7, FPGA 引脚 CLK/D0/D1/D2 = K1/F5/E3/B3, 与官方双 HDMI 例程
`4_hdmi_tx_display_A` 相同) 接 1024×600 小屏, 上电即显示. 输出 1024×600@60 Hz
(行 1024 + 40 + 128 + 152 = 1344, 场 600 + 3 + 6 + 11 = 620, 像素时钟 50 MHz, 同步负极性), DVI 编码, 不带音频.

```text
┌ 标题栏: ◆ 多媒体信息发布系统 · 运维终端        HX4S20C · EG4S20BG256 · HDMI1 1024x600@60Hz     运行时间 hh:mm:ss ┐
│ ┌ 存储与系统 ────────┐ ┌ 播放状态 ──────────┐ ┌ 画面与音频 ─────────────────┐                                 │
│ │ TF 卡 / 图片数量    │ │ 当前图片 3 / 12     │ │ 画面模式                     │                                 │

│ │ 字幕 / 字库文件     │ │ 加载进度 ■■■□ 78%  │ │ 音源 / 电平                  │                                 │
│ │ 报警状态 / 拨码开关 │ │ 特效/轮播/频谱/菜单 │ │                              │                                 │
│ ┌ 系统日志 (最近 15 条) ─────────────────────────────────────────────── 共 n 条 ┐                                   │
│ │ [00:01:21] INFO  TF 卡就绪, 图片数: 12                                         │                                   │
│ │ [00:03:10] ALARM !! 应急报警触发 !!          (红色)                            │                                   │

```

- 状态面板每 1 ms 从播放器 (`video_clk` 域) 整组采样一次 (toggle 握手, 多位值同一时刻), 数值随操作实时变化
- 日志由事件自动产生 (相邻两次采样比较): 上电、TF 卡初始化 / 扫描 / 就绪 (含图片数) / 无卡 / 文件系统错误 / 无图片、
  显示图片 #n、参数菜单开关、画面模式、报警布防 / 撤防 / **触发** / 解除、音频频谱开关、自动轮播开关、转场特效、音源、
  WAV 已加载、图片格式错误; 满 15 条后最旧的一条被覆盖, 显示时按环头偏移映射行号, 不搬移数据

**4×4 矩阵键盘** (16 个轻触开关自己焊, 参照官方例程 `2_DEMO/23_SCAN_4X4KEY`). 开关 r×c 一端接行线 A[r], 另一端接列线 B[c]:

```text
             B0 (G14)   B1 (G16)   B2 (F15)   B3 (F14)      <- 列: FPGA 扫描输出 (开漏, 当前列输出 0, 其余高阻)
A0 (H16)        1          2          3       A 下一条命令
A1 (H15)        4          5          6       B 上一条命令
A2 (J16)        7          8          9       C 上一张 (直接执行)
A3 (K15)      * 退格       0        # 执行    D 下一张 (直接执行)
 ^ 行: FPGA 输入 (内部上拉)
```

- 不需要二极管和外部电阻 (只识别单键; 列为开漏, 同一行同时按两个键也不会两路输出对顶). 引脚与官方例程相同, 在扩展排针上
- 扫描: 每列 250 µs, 一圈 1 ms, 连续 16 圈相同才接受 (消抖 16 ms); 每圈最多输出一个新按下的键, 不做长按连发 (`player/kb_matrix4x4.v`)

命令行用法: **A / B** 循环选择命令 (命令名直接写到提示符后), **0~9** 输入参数 (最多 2 位, 未选命令时数字不响应),
**\*** 退格 (没有参数时清除命令), **#** 执行; **C / D** 不经命令行直接 上一张 / 下一张. 执行后命令行清空.

| 命令 | 参数 | 作用 |
|------|------|------|
| `show <n>` | 1 ~ 图片数 | 跳到第 n 张 (显示中立即切换; 加载中改目标; 转场中记住, 转场结束后执行) |
| `next` / `prev` | — | 下一张 / 上一张 (同 C / D) |
| `mode <n>` | 0 ~ 3 | 画面模式 正常 / 日间 / 夜间 / 护眼 (一次设置亮度、对比度、色温、伽马) |
| `bright <n>` | 0 ~ 16 | 亮度 |
| `vol <n>` | 0 ~ 16 | 音量 |
| `eff <n>` | 0 ~ 8 | 转场特效 (8 = 轮换) |
| `auto <n>` | 0 / 1 | 自动轮播 关 / 开 |
| `alarm` | — | 触发应急报警 (等同 KEY1, 需 SW1 布防; 解除仍要把 SW1 拨回 0) |

- 执行成功写日志 `CMD 执行 bright 15`, 播放器状态变化本身也照常记日志 (如 `显示图片 #5`、`画面模式: 夜间`);
  不执行并写 WARN 日志的情况: 未选命令 / 参数错误 (缺少或超出范围) / 报警未布防 / 报警中 (报警抢占一切, 命令无效) / TF 卡未就绪 (换图命令)
- 换图命令在 SW3 参数菜单打开时也有效 (此时 KEY3/KEY2 归菜单)
- 终端 (`term_clk`) 到播放器 (`video_clk`): 一条命令 = `cmd_tgl` 翻转一次, 命令号 / 参数保持到下一条, `player_ctrl` 三级同步后执行

实现 (`player/term_top.v`):

| 部分 | 说明 |
|------|------|
| 显存 | 128 列 × 37 行字符 (8×16), 每格 {字符码 9 bit, 前景色 3 bit}, 两块简单双口 BRAM (`term_vram_c` / `term_vram_a`, EG_LOGIC_BRAM PDPW). **上电初值就是界面模板** (边框、面板标题、标签全部由 `python/gen_term_rom.py` 预置到 .mif, 不占逻辑) |
| 微程序引擎 | 状态字段、日志行、命令名、命令行清除都由一段 9 bit 微程序写入显存 (`term_prog_rom`, 1965 / 2048 字; 0x180 起为指令, 所以字符串中的汉字限 128 个, 只出现在模板里的汉字可用到 192 个): 字符串 (枚举名 / 日志消息)、十进制数、16 格数值条、hh:mm:ss、补空格、定位、换色共 9 种指令. 改界面只需改 Python 后重新生成, 不动 RTL |
| 渲染 | 计数器 → 显存 → 字库 (`term_font_rom`, ASCII + 制表符/图标 + 179 个汉字 (左右半字), 7776 字节) → 8 色调色板 → RGB, 4 拍流水; 标题栏 / 状态栏底色不同, 光标反色闪烁 |
| 输出 | `tmds_encoder.v` × 3 (DVI 8b/10b, 直流平衡) + 复用主屏的 `hdmi_phy_wrapper` (`lane_lvds_10_1` × 4, ODDR 10:1), 时钟通道 `0000011111`; 第 4 个 PLL `term_pll.v` 输出 50 / 250 MHz (参数取自官方 lab_ex_4 `pll_50.v`) |

### 硬件连接

HDMI 线接开发板 **HDMI_B** 口 → 显示器 (需支持 HDMI 音频才能听到声音); 另一个 HDMI 口 (HDMI1) 可接 1024×600 小屏显示运维终端 (不接也不影响主屏). TF 卡插卡槽.
输出为 1280×800@59.9 Hz; 16:10 显示器 (1920×1200 / 1680×1050 / 1440×900 等) 全屏无黑边.
若显示器菜单里的 “画面比例” 设成了 4:3 或 “点对点”, 请改成 “全屏 / 自动”.
正常播放 WAV 时 SW4 拨在 `0` 一侧 (管脚 C5, 内部上拉, 开发板手册 SW1~SW4 = C8/C7/C6/C5). SW2 (C7) 控制音频频谱, SW3 (C6) 控制参数菜单, SW1 (C8) 为应急报警布防, KEY1 (B1) 模拟传感器; 蜂鸣器 (H11) 需把板上 SW5 拨到使能.

## 3. TF 卡内容

TF 卡格式化为 **FAT32**. 推荐按文件夹分类 (素材工具 “写入TF卡” 页默认这样写):

```
TF 卡根目录
├─ IMG\      IMG01.BMP ~ IMG16.BMP     图片
├─ MUSIC\    MUSIC.WAV                 背景音乐
├─ SUB\      SUB.TXT  SUB.FNT          滚动字幕 / 字库
└─ PLAY.CFG                            播放列表 (可选): 播放顺序 + 每张显示秒数
```

| 文件 | 要求 | 用途 |
|------|------|------|
| `*.BMP` | **任意分辨率** (宽高 16~4096), 24 bit 非压缩或 32 bit, 最多 16 张; 等比缩放到 640×400 并补黑边居中. 640×400 加载最快 (大图读卡时间与文件大小成正比, 1920×1080 约为 8 倍) | 图片, OSD 显示文件名前 8 个字符和原始分辨率 |
| 第一个 `*.WAV` | PCM 8/16 bit, 单/双声道, 8000~48000 Hz | 背景音乐 |
| 第一个 `*.TXT` | 取前 512 字节 | 底部滚动字幕 |
| 第一个 `*.FNT` | 2048 字节 (128 个 8×16 字模) | 字幕用户字库 (中文) |
| `PLAY.CFG` | 文本, 不超过 2048 字节, 最多 16 行有效 | 播放顺序与每张图的显示秒数 (见下) |

- **分类文件夹**: 加载器先扫描根目录, 找到名为 `IMG` / `MUSIC` / `SUB` 的文件夹就分别从中读取图片 / 音乐 / 字幕字库,
  对应类型不再使用根目录中的文件; 没有某个文件夹时该类型仍取根目录中的文件, **旧卡 (全部放根目录) 照常使用**.
- **播放列表 `PLAY.CFG`** (可用记事本直接编辑):
  ```
  # 每行: 图片编号 显示秒数      ('#' 之后为注释)
  03 5            第 1 张播放 IMG03.BMP, 显示 5 秒
  IMG01.BMP 8     也可以写文件名
  02              省略秒数 = 默认 4 秒
  ```
  编号是 `IMGnn.BMP` 文件名中的数字 (1~16), 行的先后就是播放顺序, 调换行即可改顺序, 不必重新拷贝图片;
  秒数 1~255 (0 或省略 = 4 s), 每张图可以不同. 编号重复的行只取第一次; 卡上找不到的图片在播放时自动跳过.
  没有 `PLAY.CFG` 时按目录顺序播放, 每张 4 s. 有 `PLAY.CFG` 但没有 `IMG` 文件夹时, 列表作用于根目录中的 `IMGnn.BMP`.
- 实现 (`sd_media_loader.v`): 扫描顺序为 根目录 → 读 `PLAY.CFG` (独立的逐字节解析器, 字节晚一拍送入, 不加长主状态机的组合路径)
  → `IMG` → `MUSIC` → `SUB` → 字幕 / 字库. 有播放列表时, 目录项按 `IMGnn` 的编号查表得到 **播放位置**, 簇号 / 文件名 / 帧槽 / 预取 / 分辨率文字
  都按播放位置存放, 播放器、OSD、第二屏终端完全不用改 (它们看到的就是按列表排好的第 1~N 张); 每张的秒数随加载器应答 `ack_dur`
  送给播放器, 自动轮播间隔 = 秒数 × 60 帧.

不能把 PNG/JPG 直接改后缀. 推荐用 `doc/convert` 下的工具准备 (详见 [doc/convert/README.md](doc/convert/README.md)).
最简单的是图形界面: 双击 `doc/convert/media_tool_gui.bat` (或 `python media_tool_gui.py`),
依次在 “图片 / 音乐 / 字幕 / 写入TF卡” 四个页面操作即可. 各功能也有对应的命令行脚本:

| 脚本 | 作用 |
|------|------|
| `media_tool_gui.py` | 图形界面: 图片排序与预览、音乐转换与试听、字幕实时预览、TF 卡检查与写入 |
| `convert_images_to_bmp.py` | JPG/PNG/WebP 等批量转为 640×400 24 bit BMP (`--fit` 默认 crop 等比裁剪铺满, 另有 stretch 拉伸 / pad 补黑边). 不再必需 (BMP 可直接放卡), 但 LANCZOS 缩放质量更好、加载更快 |
| `convert_wav.py` | 任意 WAV (或经 ffmpeg 的 mp3/flac) 转为 48 kHz 16 bit PCM `MUSIC.WAV` |
| `make_subtitle.py` | UTF-8 文本 (可含中文, 最多 64 个不同汉字) 生成 `SUB.TXT` + `SUB.FNT` |
| `sync_to_sd.py` | 清空 TF 卡并写入 `IMG\IMG01~16.BMP`、`MUSIC\MUSIC.WAV`、`SUB\SUB.TXT / SUB.FNT` 与 `PLAY.CFG` (`-d 秒数` 设置时长, `--flat` 为旧版根目录布局) |

命令行典型流程:

```bash
cd doc/convert
python convert_images_to_bmp.py
python convert_wav.py 歌曲.wav
python make_subtitle.py "欢迎使用安路 FPGA 多媒体播放器!"
python sync_to_sd.py E: -w MUSIC.WAV -t SUB.TXT -f SUB.FNT
```

由于加载器按 FAT32 目录解析, 电脑上删除的旧文件不会再被读到.

**音乐格式建议 (参照第十一讲)**: 第十一讲的做法是 PC 端把任意音频转成 **48 kHz 16 bit 单声道**, FPGA 只做流式缓冲.
`convert_wav.py` / 图形界面现在默认就是 48000 Hz (Kaiser 窗 sinc 重采样, 误差 < -84 dB), 图形界面默认勾选单声道.
48 kHz 的样本与 HDMI 的 48 kHz 输出帧一一对应, 不经硬件线性插值, 音调与音质和原曲一致.
TF 卡走 SPI 单扇区读, 有效带宽约 1~2 MB/s 且要同时供给图片加载: 48 kHz 单声道需 96 KB/s, 立体声 192 KB/s.

```bash
python convert_wav.py 歌曲.mp3 --mono          # 48000 Hz 单声道 -> MUSIC.WAV
```

`--keep-rate` 保留原采样率 (8k~48k), 由 FPGA 线性插值, 文件更小但高音略有损失.

**断音排查**: 把 SW4 拨到 `1` 切到内置旋律 (`P`), 如果旋律流畅而 WAV 断续, 说明是 TF 卡供数不足 (音频位小数点也会亮);
按上面转成单声道或换一张 A1 级别的 TF 卡.

**卡顿 / 变调 / 播放不全 (已修正)**: 旧位流的 WAV 异步 FIFO 满标志有位宽错误 (见第 5 节"时序"),
每写入 16384 个样本后, 接下来的一大段数据被丢掉, FIFO 随之读空. 表现为周期性跳段 (播放不全) 和断音 (卡顿);
旧播放器读空时继续对旧样本插值、时间轴被拉长, 又使音调偏移. 两处都已修正, 请使用 release 中的新位流,
并用新工具重新转换 MUSIC.WAV.

**播放不完整排查**:
- 旧位流在任何一次扇区读超时后都会整卡重新扫描, WAV 随之从头播放. 长歌曲因此可能永远放不到结尾.
  现在超时后先在原位重读, 不再跳回开头 (见第 1 节 "可靠性").
- 音乐播完会无缝回到开头循环. 请在电脑上确认 MUSIC.WAV 本身的时长: 图形界面 “音乐” 页或 “写入TF卡” 页都会显示.
  转换时 “秒” 一栏留空才是整首; 填了数字 (或命令行加了 `--seconds`) 会只保留前 N 秒.

### 1280×800 输出 (1920×1200 屏无黑边)

原来输出 640×480 (4:3), 16:10 的 1920×1200 显示器只能在左右补黑边. 要铺满且不变形, 输出比例必须也是 16:10.
直接输出 1920×1200 需要约 154 MHz 像素时钟 (每条 TMDS 线 1.5 Gbps), 超出 EG4S20 LVDS 的 800 Mbps; 所以输出 **1280×800**
(正好是 1920×1200 的 2/3), 显示器按 1.5 倍等比放大铺满.

- **时钟** (`video_pll`, 分频与环路参数同官方 720p 例程 `PLL_HDMI_AUDIO` 的 75/375 MHz, VCO 750 MHz):
  `pix_clk` 75 MHz (HDMI 像素) / `hdmi_5x_clk` 375 MHz (串行, 每线 750 Mbps, 在 LVDS 800 Mbps 规格内) / `video_clk` 18.75 MHz (= 75/4).
- **分工**: 原合成逻辑 (开机画面、转场、OSD、菜单、亮度对比度) 最高只能跑约 27 MHz, 不能直接提到 75 MHz. 因此合成仍按 640×400 在
  `video_clk` 下工作 (每行 760 拍 = 输出 2 行), 输出端 `video_scale2x` 用 2 行乒乓行缓存把每个像素横竖各复制一次.
  SDRAM 读带宽比原来的 640×480@60 还低 (每 40.5 us 读一行 640 像素, 原来 32 us).
- **输出时序**: 1280×800 有效, 行总长 1520 (前肩 48 / 同步 32 / 后肩 160), 场总长 824 (前肩 3 / 同步 6 / 后肩 15), 59.88 Hz,
  行频 49.34 kHz 与 VESA 1280×800 RB 模式 (49.31 kHz) 基本一致; 行消隐 240 拍, 给 HDMI 音频数据岛留足空间. 非 CEA 格式, AVI 的 VIC 填 0.
- **帧对齐**: `video_scale2x` 在 `pix_clk` 域检测合成器每帧第一个有效行, 把输出计数器装载到 “第 0 行之前 2 行”;
  两边周期严格相等 (760×412×4 = 1520×824), 只有上电第一帧会真正调整, 之后不会抖动.
  读第 ly 行时写的是 ly+1 行 (另一 bank), 前后余量都在 1500 个像素时钟以上.
- **音频**: ACR 的 CTS 由 `audio_arc_calculate` 在像素时钟下实测 (约 75000), 换时钟后自动适应; `I2S_receiver` 同在 `pix_clk` 域.
- **画面布局** (640×400 坐标): 顶部信息栏 0~27 行不变; 开机画面标题 110, 信息 168, 状态 216, 进度条 256, 提示 320/344;
  参数菜单框 y 40~327 (7 项); 底部滚动字幕 368 行起. 纵向擦除 / 圆形展开按 400 行重新标定.
- **图片**: TF 卡中的 BMP 在加载时统一变成 640×400 (见下文 “任意分辨率图片”); `doc/convert` 工具仍可预先转成 640×400 (等比裁剪铺满).

### 任意分辨率图片 (bmp_fit_scaler)

参照第十三讲 “图片缩放与缩略图” 扩展要求 3 “支持不同分辨率图片”, 以及第五讲 `bmp24_decoder.v` 的行跨度 / 自上而下处理.
思路是 **加载时归一化**: 任意 W×H 的源图在写入 SDRAM 前就被缩放成完整的 640×400 帧 (含黑边), 帧槽布局、显示读、
8 种转场、亮度对比度、OSD 与 2×2 放大全部不用改, 写入长度仍是 256000 字.

- **支持**: 宽高 16~4096; 24 bit (BI_RGB) 或 32 bit (BI_RGB / BI_BITFIELDS, 忽略 alpha); 每行补齐到 4 字节; 高度为正 (自下而上) 或为负 (自上而下).
  其余 (RLE 压缩、16/8 bit、超出范围、文件截断) 与原来的损坏图片一样应答失败并跳过. 目录扫描不再按文件大小过滤 (只要求 ≥ 54 字节).
- **几何**: `W*400 ≥ H*640` (比屏幕宽) 时 dw = 640, dh = H*640/W, 上下补黑; 否则 dh = 400, dw = W*400/H, 左右补黑. 每张图一次除法 (10 拍移位相减, 商 ≤ 640),
  乘常数用移位相加, **不占 DSP**. 黑边 pad_l = (640-dw)/2, 先输出的黑边行 (400-dh)/2.
- **最近邻映射**: 目标像素 k 取源像素 ⌊k·W/dw⌋, 目标行 j 取源行 ⌊j·H/dh⌋ (按文件行顺序). 全部用 DDA 符号位判断, 每像素只做加法:
  - 填充端: 源比目标大的方向先**抽取** (`f = k·W − (x+1)·dw < 0` 时该源像素被选中, 行同理), 选中的像素写入 2048×24 bit 环形行缓存, 每行最多 640 像素;
    存满 min(H, dh) 行后 `need=0`, 加载器不再读后面的扇区 (大图缩小时省掉多余的读卡).
  - 输出端: 逐行产生 640 个像素 (黑边 / 图像), 源比目标小的方向用同样的 DDA **重复**像素和整行, 一行最后一次使用后释放缓存. 每像素 4 拍, 写 FIFO afull (门限 448) 时暂停.
- **流控**: 一个扇区最多 171 个像素 (24 bit), 加载器每读一个图片扇区前等待缓存剩余 ≥ 256 像素 (`room`); 小图放大很多倍时输出端慢于输入, 读卡自动降速, 缓存不会溢出.
- **垂直翻转**: 自下而上存储的图仍由 `frame_fifo_write` 翻转写地址; 自上而下存储的图 `write_vflip=0` 关闭翻转.
  BMP 头在 `write_req` 之后才读到, 所以 `frame_fifo_write` 改为在本帧首个突发开始前 (写 FIFO 已攒够 128 字) 才按 `write_vflip` 装载起始地址.
- **质量与速度**: 最近邻缩小有轻微锯齿; 想要更平滑可先用 `doc/convert` 的 LANCZOS 预转换. 加载时间约与文件大小成正比 (640×400 为 750 KB, 1920×1080 为 6 MB).

### 时序

约束在 `src/user_source/constraints_source/timing.sdc`, 各时钟域之间已声明为异步时钟组 (跨域信号全部经同步器或异步 FIFO).
`ext_mem_clk` 与其相移时钟 `clkc[2]` (SDRAM 输出时钟) 之间的路径为原例程 SDRAM 控制器固有, 板级已验证工作正常.
为满足 100 MHz 的 `sd_card_clk`, 加载器对 SD 读数据、帧槽替换判定、WAV 补数判定均插入了寄存器级;
超时计数器 `tmr` 的 7 个超时比较提前一拍寄存 (比较 K-1, 清 0 后一拍用 `tclr` 屏蔽), BMP 头偏移 `f_off` 的比较也提前寄存 (TF 卡相邻字节至少间隔 32 个时钟);
`frame_dual_read_write` 中对写 FIFO 的 `rdusedw` 也做了寄存, 缩短 125 MHz 域的突发判定路径.
WAV 异步 FIFO (`async_fifo.v`, 8192 深, 跨 8 块 BRAM32K) 的对端指针与满标志都寄存一拍
(用上一拍数据量与 2^AW-2 比较, 少用 2 个单元). 原组合满判定 (格雷码转换 + 减法 + 比较) 直接驱动 BRAM 写使能, 在 100 MHz 下差 0.18 ns.
注意数据量必须按 AW+1 位取模: 第一版写成 `(wptr - rptr_w) >= ((1 << AW) - 2)`, 常数为 32 位,
整个比较按 32 位进行, 写指针回绕后差值变成很大的正数, 满标志误报, 读指针回绕前的写入全部被丢掉.
现改为先算 AW+1 位的 `wr_level` 再与同位宽常数比较 (`tb_audio` 逐样本核对 FIFO 读出与写入一致).

HDMI 串行化 (`lane_lvds_10_1.v`) 修正:
- `pix_clk` 与 `hdmi_5x_clk` 同源同相 (1:5), 二者之间设为 exclusive, 这段跨时钟路径不做时序检查.
  `video_clk` (= `pix_clk`/4) 与 `pix_clk` 放在同一时钟组, `video_scale2x` 中 `video_clk` → `pix_clk` 的寄存器路径按同步路径检查.
- 原例程在像素沿后第 5 个串行沿装载 TMDS 字, 这个沿正好是 TMDS 字更新的那个沿. 取到旧值还是新值只取决于两棵时钟树的偏斜.
- 芯片升温后会偶发取错位, 表现为静止画面一段时间后出现随机闪烁的花点.
- 现改为在像素沿后第 2~3 个串行沿装载, 落在稳定窗口的中间: 原 25 MHz 时窗口 40 ns、前后余量 >= 16 ns;
  现 75/375 MHz 时窗口 13.3 ns, 装载沿在像素沿后 5.3~8 ns, 前后余量 >= 5.3 ns.

SDRAM 行刷新 (`frame_dual_read_write.v`):
- 板上现象: 在一张图上停留一段时间后, 切到其他缓存图片时出现越来越多的固定花点, 而一直显示的那张图正常.
- 原因: 正在显示的图每帧都被读一遍, 读操作的激活/预充电顺带刷新了这些行; 其他缓存图片所在的行没人访问, 电荷流失后数据出错.
  说明 SDRAM 控制器的自动刷新没有起作用. 原例程 `global_def.v` 中 `SELF_REFRESH_INTERVAL` 宏缺括号, 计算结果为 0.
- 修正: 仲裁器每 900 个周期 (7.2 us) 插入一次整行 256 字突发读, 依次访问 8192 行 (row + bank), 59 ms 扫完全部行, 满足 64 ms 刷新要求.
  读回数据丢弃. 行刷新只在两次突发之间插入, 与读写互斥, 显示读优先; 每次约 270 个周期, 占用约 30% 的 SDRAM 时间,
  转场时两路显示读 + 行刷新合计约 60%, 仍有余量 (仿真无欠载).
- 第一版行刷新用单字读 (每次约 13 个周期), 花点消失了, 但图片上出现闪烁的彩色竖条, 位置固定在 x = 0/128/256/384/512,
  正好是每个 256 字突发的开头 (SDRAM 行首; 行宽 640 字 = 2.5 个突发, 所以奇偶行错开 128). 仲裁逻辑在理想 SDRAM 模型下仿真正确,
  说明是 SDRAM 控制器 (加密 IP) 对单字读之后的突发处理有问题. 改为与显示读完全相同的整行突发后, 控制器只会看到原例程验证过的访问方式.

## 6. Flash 固化与上电自启

参照第六讲 (完赛系列 “Flash 固化与上电自启”) 的四项优化.

### 上电启动顺序

```text
上电 → 配置芯片从 SPI Flash 读位流 (mclk 29 MHz, x1) → 配置完成, 用户逻辑开始运行
     → sys_pll / video_pll / PLL_HDMI_AUDIO 全部锁定
     → 6 个时钟域 (clk / sd_card_clk / ext_mem_clk / video_clk / pix_clk / audio_mclk) 各自经 reset_sync 同步释放复位
     → SDRAM 控制器初始化, 同时 HDMI 输出开机画面 (不读 SDRAM)
     → Sdr_init_done 同步到 sd_card_clk 后释放 TF 卡加载器复位 → 扫描 TF 卡 → 显示第一张图
```

对应代码 (`top_tf_hdmi_audio.v` 时钟/复位段):

| 优化 | 做法 |
|------|------|
| 一: 复位同步器 | `reset_sync.v`: 3 级, 异步置位、同步释放. 每个时钟域一个, 复位按键不再直接进入任何模块 (数码管扫描原来直接用 `rst_n`, 现在也经 `clk` 域同步器) |
| 二: PLL 锁定参与复位 | 三个 PLL 的 `extlock` 全部参与复位: `rst_all = ~rst_n \| ~sys_pll_lock \| ~video_pll_lock \| ~audio_pll_lock`. 原来只用了音频 PLL 的锁定信号. PLL 的 `reset` 接复位键, 按下时 PLL 重新锁定 (`sys_pll.ipc` / `video_pll.ipc` 已打开 `pll_lock`, 重新生成 IP 时锁定端口会保留) |
| 二: 启动序列 | `Sdr_init_done` (ext_mem_clk 域) 经 `sync_2ff` 同步到 sd_card_clk 后产生加载器复位 `rst_ld`. SDRAM 初始化完成前加载器保持复位, 不会写入首图. SDRAM 读侧原本就以 `Sdr_init_done` 为条件 |
| 三: 时序约束 | `timing.sdc` 增加 `set_false_path -from [get_ports {rst_n}]`. 复位按键只进同步器的异步端和 PLL reset, 不需要时序分析. 各时钟域之间原来就已声明为异步时钟组 |
| 四: Flash 固化 | `cli_build.tcl` 同时生成 `.bit` 与 `.bin`; 新增 `flash_program.tcl` 用命令行烧写并回读校验 |

不需要另加上电延时计数器: 三个 PLL 锁定需要几十微秒到几毫秒, 这段时间电源已经稳定.
复位按键 (A2) 按下时整个系统 (包括 PLL) 复位, 松开后按上面的顺序重新启动, 效果与重新上电一样, 只是不重新加载位流.

## 7. 仿真

`src/sim` 下有四个自检仿真, 使用 Icarus Verilog 与 Python 运行, 详见 [src/sim/README.md](src/sim/README.md):

- **`tb_loader`**: 用 Python 生成一个 FAT32 镜像, 其中故意放入 MBR 分区、不连续的根目录、长文件名、已删除项、损坏 BMP、碎片化文件, 以及带 LIST 块的 WAV. 仿真依次核对:
  - 扫描结果
  - 整帧像素哈希
  - 损坏图片应答
  - 缓存命中的切换延迟 (19 个时钟周期)
  - WAV 样本序列与循环
  - 瞬时读超时 (400 ms) 后原位重读: 状态保持就绪, WAV 不从头开始, 图片缓存保留
  - 拔卡、插卡后重新扫描
- **`tb_loader` 任意分辨率模式** (`sh run_sim.sh fit`): `mkdisk.py --fit` 生成 12 张图: 800×500 (缩小)、1000×333 (上下黑边)、301×500 (左右黑边, 每行补 1 字节)、
  160×100 (放大 4 倍)、202×150 自上而下存储、123×77 32 bit、17×900 (水平放大 + 垂直缩小)、4096×16 (只剩 2 行), 以及 RLE 压缩 / 截断 / 15×15 / 4097 宽 4 张应拒绝的图.
  Python 参考模型 `fit_frame` 算出期望的 256000 字, 逐张核对哈希与翻转标志; 写 FIFO afull 随机拉高 3/8 的周期检查反压, 并监视行缓存不溢出.
- **`tb_loader` 分类文件夹模式** (`sh run_sim.sh folder`, 约 3 分钟): `mkdisk.py --folder` 生成的卡根目录有 `IMG` / `MUSIC` / `SUB` 文件夹、
  名字相近的干扰文件夹 `IMGX`、不应再使用的旧图片 / 旧 WAV / 旧字幕, `IMG` 文件夹内目录顺序与编号不同, 并含 TXT 与已删除项;
  `PLAY.CFG` 含注释、`IMG01.BMP 8` 文件名写法、省略秒数、卡上没有的 `07`、重复编号和没有换行的最后一行.
  核对: 位置数 = 5, 每个位置的图片帧哈希 / 文件名 / 分辨率文字 / `ack_dur` 秒数, 缺失图片应答失败, 字幕字库来自 `SUB`,
  WAV 样本序列来自 `MUSIC\MUSIC.WAV`; 再用 `--nocfg` (无播放列表) 核对按 `IMG` 目录顺序、秒数全为 0 (默认). 两次均 PASS.
  播放器侧 (`tb_termcmd`): 应答带不同秒数时, 自动轮播在每张图停留 120 / 240 (默认) / 60 帧, PASS.
- **`tb_loader` 热插拔模式** (`sh run_sim.sh hotplug`): 加载器按 `CLK_HZ = 10 MHz` 例化, 超时与心跳按周期数缩短 10 倍 (逻辑不变). WAV 停止消费、图片全部命中缓存 (测试音模式), 核对: 空闲 1.6 s 心跳 3 次且不影响就绪状态和缓存; 空闲时拔卡 → 无卡 → 插回重新扫描; 0.1 s 内换上序列号不同、少一张图的卡 → 重新扫描出 2 张图; 同一张卡瞬时无响应 → 重新初始化后序列号相同, 不重新扫描.
- **`tb_loader` 压力模式** (`sh run_sim.sh stress`): SD 模型换成接近实际 TF 卡的时序 (每字节 36 周期, 访问延迟 0.1/1 ms, 每 1000 次读一次 40 ms 长延迟), WAV 为 48 kHz 立体声并按实时速率消费, 统计加载图片期间的 FIFO 欠载.
- **`tb_video`**: 导出开机画面、8 种转场、OSD 各状态的画面 PNG (640×400), 并对转场混合结果逐像素核对.
- **`tb_scale2x`** (`sh run_sim.sh scale`, 约 1 分钟): 640×400 内容时序 + 模拟合成器 → `video_scale2x`, 逐像素核对 1280×800 输出
  (每个输出像素 = 内容像素 (x/2, y/2), 同一输出帧来自同一内容帧), 并检查行/场总长、有效区、HS/VS 位置与宽度.
- **`tb_spec_unit`** (`sh run_sim.sh spec`, 约 1 分钟): 1 kHz / 200 Hz+3 kHz / 60 Hz / 白噪声 / 静音 5 个用例, FFT 全部 1024 点与
  24 个频段高度和 Python 定点模型逐位一致, 纯音相对浮点 FFT 的 SNR 约 60 dB, 峰值落在正确频段.
- **`tb_spec`** (`sh run_sim.sh spec`, 约 10 分钟): 画面级检查, SW2 关闭时不叠加任何内容; 打开后背景透明;
  200 Hz + 3 kHz 时最高的两根柱在对应频段; 静音后柱子回落、峰值帽保持.
- **`tb_alarm`** (`sh run_sim.sh alarm`, 约 15 分钟): 应急报警. 控制: 未布防不触发、布防后触发并锁存、报警中按键与菜单不响应、计时进位与 99:59 封顶、SW1 解除; 画面: `check_alarm.py` 按 `alarm_screen.v` 的算法逐像素核对整帧报警画面 (SW2 打开也不叠加频谱), 在第 100 行触发时本帧整帧正常、下一帧整帧报警 (硬切不撕裂), 解除后恢复原图, 开机画面上也能报警, 滚动字幕在报警第一帧从屏幕右边外开始、之后逐帧左移 (模型含字幕位置, 仍整帧逐像素一致); 音频: 按过零点测警笛频率 (起点约 645 Hz、1 s 处约 1480 Hz、2 s 回到约 620 Hz), 蜂鸣器同频, 幅度 ±16383 且音量 0 时照常输出, 报警期间不读 WAV FIFO, 解除后样本序列从断点继续.
- **`tb_menu`** (`sh run_sim.sh menu`): SW3 菜单按键逻辑 (7 项、模式预设正反循环、各项加减与上下限、复位)、画面查找表逐像素核对
  (亮度/对比度沿用原公式且默认值与原图逐位相同; 偏暖 / 偏冷 / 伽马 4 / 伽马 12 / 夜间预设按 Python 模型逐像素核对, 模型直接 import
  `gen_gamma_rom.py`, 并检查色温与伽马的方向)、帧边界锁存、音量增益表.
- **`tb_term`** (`sh run_sim.sh term`): 第二屏运维终端. 状态源 (18.75 MHz) 依次产生 19 个事件 (日志环回绕);
  4×4 开关矩阵模型经真实的 `kb_matrix4x4` 扫描消抖输入: A/B 选命令、数字 (第 3 位忽略)、退格、# 执行 (成功 / 参数超范围 / 缺参数 /
  未选命令 / 未布防 / 报警中), C/D 快捷, 两键同时按下; 逐条核对输出命令号与参数 (7 条).
  `check_term.py` 用 `gen_term_rom.py` 参考模型重放记录的日志与按键, 显存 4736 格逐格一致, 整帧 1024×600 逐像素一致;
  仿真内检查行 / 场总长 (1344 × 620)、HS 位置与宽度、DE 1024 × 600, TMDS 每个像素符号解码回原像素、消隐期控制码 = {VS, HS}、直流偏差有界.
  仿真画面输出到 `frames/term_sim.png`.
- **`tb_termcmd`** (`sh run_sim.sh term`): 终端命令 → `player_ctrl` (带加载器应答模型): show 跳转 (显示中 / 等待中改目标 / 转场中挂起)、
  next/prev 回绕、show 越界忽略、mode/bright/vol/eff/auto 生效、菜单打开时换图命令有效而 KEY3 归菜单、原按键照常、
  alarm 未布防不触发 / 布防后触发、报警中命令全部忽略、解除后恢复.
- **`tb_sdram_arb`**: SDRAM 仲裁器在双路显示读与帧写入同时进行时的数据正确性, 以及行刷新是否覆盖全部 8192 行.
- **`tb_audio`** (`sh run_sim.sh audio`): WAV FIFO + 播放器 + I2S 接收. 输入左 1 kHz / 右 440 Hz 正弦, FIFO 缩到 1024 深使指针频繁回绕:
  逐样本核对 FIFO 读出顺序, FFT 检查输出频率 (音调) 与幅度、断续; 限速供数 (85%) 时检查欠载暂停后音调不变、无跳样本.
